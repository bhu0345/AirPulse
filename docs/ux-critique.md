# Macs Fan Control — 用户视角不足分析

对照对象：本机安装的 **Macs Fan Control 1.5.21**（CrystalIDEA，Qt，`LSUIElement` + `smcwrite` 特权 helper）。

## 1. GUI：像工具面板，不像现代 Mac 应用

| 问题 | 用户感受 |
|------|----------|
| Qt 双列表（左风扇 / 右传感器） | 信息密度高但层级扁平，第一眼不知道「我现在该点哪里」 |
| 大量传感器平铺 | 多数场景只关心 CPU/GPU/电池温度，却占满半屏 |
| 主操作为「每行一个 Auto / Custom…」 | 控制被藏在次级对话框里，主窗口几乎只是监视器 |
| 空间浪费 | 宽窗口 + 分割条，真正交互（调速）却要再弹窗；菜单栏 popover 也很浅 |
| 视觉陈旧 | 系统标准控件堆砌，缺少状态强调（当前模式、噪声档位、温度趋势） |

**用户真正想要的主界面：**打开就能看到「现在多热、风扇多快、一键改安静/凉快」，而不是先在两张表里找按钮。

## 2. 风扇控制：双风扇被当成两台独立机器

| 问题 | 用户感受 |
|------|----------|
| 左右风扇各自 Custom | MacBook Pro 双风扇几乎总是应同步；分别调等于重复劳动 |
| 想同时调两侧不现实 | 没有「联动主滑杆」；预设也偏静态，菜单栏快捷不足 |
| Constant / Sensor-based 藏在对话框 | 日常只想 Quiet / Auto / 拉一把总 RPM，却要理解两种模式 |
| 反馈弱 | 调完后主窗口对「已联动 / 当前档位」表达不清晰 |

**用户真正想要的控制模型：**默认 **左右联动一个主滑杆 + 3～4 个一键预设**；需要时再「解锁分别控制」。

## 3. 额外体验债（AirPulse 需避开）

- **监控与控制割裂**：菜单栏能看数，但调速仍依赖完整窗口。
- **传感器过载**：没有「关键温度」默认视图。
- **Apple Silicon 现实**：`thermalmonitord` 会抢回风扇控制；纯 UI 重写不够，底层必须做硬件探测（`F%dmd` / `F%dMd`、可选 `Ftst`）、周期重申目标转速、退出恢复 Auto，并有过热安全回退。

## 4. AirPulse 的直接对策

1. 菜单栏优先的紧凑 popover（状态 + 主控制同屏）。
2. 默认联动主滑杆；高级区才可解除联动。
3. 一键预设：`Auto` / `Quiet` / `Balanced` / `Cool`。
4. 主界面只显示关键温度；详情窗口再列全部传感器。
5. 退出 / 崩溃 / 过热时恢复系统 Auto 或抬高风扇。
